# Feature status

The reference projects are [Spicy Lyrics](https://github.com/iPixelGalaxy/spicy-lyrics/tree/dev) and [Spotify Plus](https://github.com/iPixelGalaxy/spotify-plus). Their JavaScript extensions are not loaded into SpotiFlex. The desktop uses a Tauri/React interface backed by Rust services; the optional egui interface remains available.

Spotify's public API does not expose playlist folders. Local folders are maintained by SpotiFlex and do not change the user's Spotify folders. The [2026 development-mode changes](https://developer.spotify.com/documentation/web-api/tutorials/february-2026-migration-guide) also restrict reading playlist contents to playlists the user owns or collaborates on. Other playlist names can still appear in the library even when their contents cannot be fetched through this API.

Controls for modifying Spotify's own web menus, Spicetify developer tools, and injected experimental-feature dialogs do not apply to this standalone client.

Playback regression tests reproduce buffer starvation during a 150 ms producer scheduling gap and a two-second lyric rewind after delayed decoder feedback. The output queue now retains 250 ms of audio, native position observations subtract queued output latency, and backward drift corrections preserve forward lyric motion. Explicit backward seeks still apply immediately. These checks do not establish audible playback quality on another computer.

The native clock stops advancing after 500 ms without a fresh observation. Repeated song positions hold lyrics during narration or buffering. Remote playback retains its clock between Web API polls.

Desktop output defaults to This computer. Incoming playback updates do not change the selected output; other devices remain selectable in the device menu. Native Play restores the saved or current song when the connection has no loaded track, including after reconnects and unrelated transport commands. Stopped playback clears that loaded state. Saved sign-in checks show a locked startup screen instead of briefly mounting first-run setup.

Native connection readiness and failures are retained until the matching account completes sign-in. A connection established before the profile check finishes can then accept Play without requiring a manual reconnect. Play retries a failed native connection while preserving the pending selection.

Artist and album headers load through native catalogue requests independently of the Web API worker. Known artist names appear as soon as navigation starts. Account-scoped metadata caches retain up to 512 headers with artwork URLs, artist overviews and album details across restarts; cached details render before background refresh. Current music and nearby artist links are prefetched, with six-hour reuse for speculative requests. Shared image decoding warms banners and profile pictures. Album basics render before optional stream-count enrichment; partial updates preserve cached duration and other stream counts. Previously unseen metadata and artwork still require network access.

Read-only verification on 2026-10-18 returned six account-specific Daily Mixes, twenty recent items, personalized release and station shelves, and a five-track DJ session with a next-page URL. A DJ intro was synthesized, downloaded and decoded into 336,384 interleaved samples. The user confirmed DJ playback in SpotiFlex on 2026-10-18. Multi-set continuation and the new fades still need live verification.

Live checks on 2026-10-17 verified native play/pause after repeated click bursts, Spotify Canvas loading as a muted loop (7.25 seconds for High Forever), the current desktop artist header field, and album play counts. Internal Spotify catalogue queries may change; missing data falls back to the public catalogue. Creator IDs resolve to canonical profile handles before opening an isolated native window. Live checks verified Canvas suppresses album ambience and fullscreen exit restores the maximized work area. Native skip testing verified that the displayed track follows the loaded queue. Resume records retain the loaded queue, and track-title album links resolve missing IDs through native metadata. Full fork parity and independent audible-output verification remain unfinished.

Narration transition tests cover stereo fade direction, speech labels during overlap, unchanged music without narration, and seek buffer resets. Connect tests cover direct resume from pause, ignored stopped-session events and clock corrections that must not resume playback. Local pins and recents persist separately for each signed-in account. Discord presence itself has not been verified.

The player DJ button distinguishes click from a 500 ms hold. Click refreshes the DJ selection. Hold shows an availability notice and suppresses refresh on release. Text/voice request transport remains unimplemented; the hold gesture does not record or submit audio. Cancelling a hold prevents delayed actions, and keyboard refresh remains available.

Native reconnect stays idle until playback is requested. A same-song takeover claims the local device before accepting decoder positions; the UI starts a new clock observation even when loading and playing events arrive together. Regression tests reproduce the prior 1:17 display against audio at 0:01.2.

DJ transitions duck music under speech rather than fading the final words to silence. Music rises after the spoken line ends. End-of-track waits for submitted PCM to drain before advancing, preserving buffered narration tails. Synthetic audio tests cover audible final syllables and output completion; the revised transitions still need live listening confirmation.

DJ resume records its existing session and track UID rather than converting the current song into a standalone playback request. A skipped track is selected after resolving the session and any required next page. If Spotify regenerated UIDs, the track URI provides a fallback. Old saved files remain readable; recent playback context and passive Connect transfer metadata can recover DJ origin where Spotify still provides it. An expired session starts a fresh DJ selection. Native saved positions use the latest decoder observation so held narration positions do not advance while speech plays.
