# Feature status

The reference projects are [Spicy Lyrics](https://github.com/iPixelGalaxy/spicy-lyrics/tree/dev) and [Spotify Plus](https://github.com/iPixelGalaxy/spotify-plus). Their JavaScript extensions are not loaded into SpotiFlex. The desktop uses a Tauri/React interface backed by Rust services; the optional egui interface remains available.

Spotify's public API does not expose playlist folders. Local folders are maintained by SpotiFlex and do not change the user's Spotify folders. The [2026 development-mode changes](https://developer.spotify.com/documentation/web-api/tutorials/february-2026-migration-guide) also restrict reading playlist contents to playlists the user owns or collaborates on. Other playlist names can still appear in the library even when their contents cannot be fetched through this API.

Controls for modifying Spotify's own web menus, Spicetify developer tools, and injected experimental-feature dialogs do not apply to this standalone client.

Live checks on 2026-10-17 verified native play/pause after repeated click bursts, Spotify Canvas loading as a muted loop (7.25 seconds for High Forever), the current desktop artist header field, and album play counts. Internal Spotify catalogue queries may change; missing data falls back to the public catalogue. Creator IDs resolve to canonical profile handles before opening an isolated native window. Live checks verified Canvas suppresses album ambience and fullscreen exit restores the maximized work area. Native skip testing verified that the displayed track follows the loaded queue. Resume records retain the loaded queue, and track-title album links resolve missing IDs through native metadata. Full fork parity and independent audible-output verification remain unfinished.
