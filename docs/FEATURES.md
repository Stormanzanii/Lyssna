Spotify's public API does not expose playlist folders. Local folders are maintained by SpotiFlex and do not change the user's Spotify folders. The [2026 development-mode changes](https://developer.spotify.com/documentation/web-api/tutorials/february-2026-migration-guide) also restrict reading playlist contents to playlists the user owns or collaborates on. Other playlist names can still appear in the library even when their contents cannot be fetched through this API.

Controls for modifying Spotify's own web menus, Spicetify developer tools, and injected experimental-feature dialogs do not apply to this standalone client.

Playback regression tests reproduce buffer starvation during a 150 ms producer scheduling gap and a two-second lyric rewind after delayed decoder feedback. The output queue now retains 250 ms of audio, native position observations subtract queued output latency, and backward drift corrections preserve forward lyric motion. Explicit backward seeks still apply immediately. These checks do not establish audible playback quality on another computer.

Song selection, Next and Previous invalidate old queued samples immediately, before Spotify Connect responds. Decoder track identity prevents a superseded selection from becoming audible; automatic transitions retain gapless output. State uploads remain ordered and coalesce while local transport commands continue. Regression tests cover old buffered audio, rapid selections, same-song restarts, stale seek feedback and delayed uploads. Live listening still needs confirmation.

Startup metadata and audio keys reuse bounded five-minute caches owned by the current player session. Audio opening and key retrieval overlap; direct selections begin preparing before Connect finishes routing them. The next queued song preloads as soon as the current decoder is ready, and audio-output initialization overlaps connection setup. A live Windows timing run measured a 486 ms first selection and 104 ms median for subsequent sequential selections; the previous baseline median was 595 ms. A separate skip run improved from 431 ms to 58 ms median. These measure the first sample consumed by the output pipeline, excluding physical speaker latency; network conditions still affect uncached starts. Opt-in tests are `live_track_start_latency` and `live_skip_start_latency`, which use saved sign-in and play six short selections.

Windows icons share the same logo geometry across the executable, window and legacy UI. The ICO includes alpha and AND transparency masks for consumers that ignore alpha. Native audio sessions explicitly expose the executable icon and SpotiFlex name to volume controllers. Tests validate every bundled icon size; Stream Deck display still needs manual confirmation.

Temporary native connection failures retry with cancellable 1–30 second backoff. Authentication and Premium failures require user action. Repeated Play requests reuse an active or connecting session, and local audio state takes precedence over a stale UI readiness snapshot. A queued selection runs after reconnection; otherwise playback waits for Play. Live tests verified recovery after deliberate session shutdown without browser authorization, and selected-song resume without reconnecting. The connecting notification clears once Ready arrives; connecting or failed local audio no longer displays a playing state.

Local song changes use artist metadata from the current track and account cache, plus the native Connect queue. They no longer read artists or the queue through the Web API. Playback polling also skips the Web API while a native track is loaded, including while paused. Remote-device playback retains its Web API reads. During a known cooldown, startup reuses the account's cached library and defers its refresh without repeated error notifications. Existing server cooldowns remain enforced; optional catalogue enrichment and explicit Web API operations still consume quota.

A live check resolved two upcoming native queue tracks in the requested order and resumed the selected song without reconnecting. The offline regression asserts zero Web API calls across three local song-detail requests and a playback poll, while preserving the remote-device queue lookup.

Live checks opened the system default by name and verified missing-device fallback without playing audio. Browser tests cover choice persistence and refreshing devices. Audible switching between distinct physical outputs still needs manual confirmation.

The native clock stops advancing after 500 ms without a fresh observation. Repeated song positions hold lyrics during narration or buffering. Remote playback retains its clock between Web API polls.

Ctrl + + (including Ctrl + = and numpad Add) increases interface zoom; Ctrl + - decreases it; Ctrl + 0 resets to 100%. Zoom persists across restarts, supports 75–200%, and works while a text field has focus.

Saved-song resume loads the queue and saved position in one native request. After audio sign-in, the saved track is prepared at that position without activating this device or starting playback. DJ preparation reads the existing session and matches the saved track occurrence; it does not consume a fresh selection. Matching pending audio downloads are reused. Late preparation cannot replace a playback selection. Play can still wait on Spotify when preparation has not finished.

Native request transport uses Spotify's advertised per-item prompt signal and current list revision. Windows voice capture reads Windows Default microphone directly through CPAL/WASAPI. It mixes channels and resamples to mono 16 kHz PCM for local Whisper small.en decoding. Windows dictation and its confidence scores no longer gate recording or recognition; “Play Rammstein” now reaches the local model even when Windows cannot recognize that artist. Audio stays in memory. There are no artist-specific runtime corrections. Bounded artist names from the current track and visible library provide local vocabulary hints. Both hinted and unfamiliar artist requests are tested. Recognized words appear while Spotify prepares music and in the completion notice, without replacing the typed draft.

The verified 190 MB English model loads on a worker when microphone input is requested. It stays available within that Ask DJ dialog and is released when the dialog closes, after any cancelled worker exits. Dialog IDs prevent an old close event from releasing a newer dialog's model. When weights are missing, first microphone use downloads them from a pinned HTTPS revision, checks the size and SHA-256, and loads only verified bytes. Redirects are limited to approved model-host domains. Opening Ask DJ prepares Spotify request metadata without loading the speech model or opening the microphone. The request dialog shows preparation if necessary, listening, then local recognition. Only the decoded text reaches Spotify; automatic submission never fills the typed draft.
